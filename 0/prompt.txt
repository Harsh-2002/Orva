## Recommendation: replace go-selfupdate with a small in-repo `internal/selfupdate` package (Candidate 1)

`go mod why golang.org/x/crypto/openpgp` confirms the chain is `cli/commands → go-selfupdate → x/crypto/openpgp`, and it is imported **unconditionally** in the library's `validate.go` (the `PGPValidator` type links `openpgp.CheckDetachedSignature`). There is no build tag to strip it and no upstream fix. So any solution that keeps go-selfupdate on the graph keeps the vuln.

The decisive fact is **how little of the library Orva actually uses**, and that Orva already re-implements most of it:

- **Asset resolution** = list GitHub releases, pick greatest semver whose asset matches `^orva-cli-&lt;os&gt;-&lt;arch&gt;`, plus find `checksums.txt`. (go-selfupdate does this via `go-github`; ~40 lines with `net/http` + `encoding/json`.)
- **Download + verify** = fetch the asset, sha256 it, compare against `checksums.txt`. Orva **already owns** `fileSHA256`, `parseChecksums`, `remoteAssetSHA`, `remoteBuildDiffers`, and `scripts/install.sh`'s `verify()` does the identical thing.
- **Atomic swap** = the classic write-`.new` / rename-old / rename-new / remove-or-hide-old dance in `update.Apply` — about 30 lines, and Orva's release assets are **raw uncompressed binaries** (`orva-cli-linux-amd64`, `...windows-amd64.exe`), so the entire tar/zip/xz/bz2 decompression machinery is dead weight for us.

Removing the single import in `upgrade.go` drops the whole subtree — I verified none of these are referenced anywhere else in the repo (only in `/pkg/mod`): `go-github/v86`, `code.gitea.io/sdk/gitea`, `gitlab-org/api/client-go`, `hashicorp/go-retryablehttp`, `42wim/httpsig`, `go-fed/httpsig`, `davidmz/go-pageant`, `ulikunitz/xz`, and `x/crypto/openpgp`. `x/crypto` itself **stays** (backend uses `x/crypto/bcrypt`), but the openpgp package becomes unreachable → govulncheck clears. Because `upgrade.go` is bundled into the server binary too, this removes openpgp from **both** binaries in one edit.

**Why not the alternatives:**
- **Fork + `replace` (2):** You still carry the entire heavy tree (go-github, gitea, gitlab, retryablehttp, httpsig, pageant, xz), you must split `PGPValidator` into a build-tagged file (a real upstream-diverging patch since it's imported unconditionally), and you own a fork you must rebase forever — all to keep code you never call. Strictly more maintenance than owning ~150 lines you fully understand.
- **Accept + suppress (3):** Leaves deprecated, unmaintained PGP crypto linked into a security-sensitive serverless platform's server binary, and every future `govulncheck` run re-flags it. Doesn't touch the root cause.

Candidate 1 is the only option that removes the root cause *and* shrinks the attack/dependency surface, and the code we take ownership of is small, stable, and already partially ours.

New repo-root package `internal/selfupdate/` — same tier as `internal/client` and `internal/ids` (the established precedent for shared, self-contained, well-tested utilities that both binaries link). It is the right home specifically because it needs OS-build-tagged files, which would be noise inside `cli/commands` (which has none today), and it gets its own focused test target. `cli/commands/upgrade.go` stays as the thin Cobra adapter.

```

  github.go         # GitHub REST v3: listReleases(owner,repo) -&gt; []release JSON; GITHUB_TOKEN/GH_TOKEN auth

  hide_windows.go   # //go:build windows   -&gt; SetFileAttributesW via syscall (no x/sys dep)
  selfupdate_test.go / apply_test.go / checksums_test.go
```

Clean separation for unit-testing — each stage is a pure function with an injectable `*http.Client`:

```go

    OS, Arch     string
    AssetFilter  string       // "^orva-cli-&lt;os&gt;-&lt;arch&gt;", compiled to regexp
    ChecksumFile string       // "checksums.txt"

type Release struct {
    Tag          string           // raw "v2026.05.30"
    Version      *semver.Version  // parsed for comparison
    AssetName    string           // "orva-cli-linux-amd64"
    AssetURL     string           // browser_download_url
    ChecksumsURL string           // browser_download_url of checksums.txt  (== old ValidationAssetURL)
}
func (r *Release) VersionString() string          // semver String(), matches old .Version()

func DetectLatest(ctx context.Context, cfg Config) (*Release, bool, error)
```

`DetectLatest` replicates go-selfupdate's semantics exactly: list releases (first page, `per_page=100`), skip drafts/prereleases, extract semver via `\d+\.\d+\.\d+` from the tag, keep the release whose asset name matches the anchored filter, pick the greatest version, and capture the `checksums.txt` asset URL from that same release. Honor `GITHUB_TOKEN` (and `GH_TOKEN`) so the CI upgrade round-trip keeps its authenticated rate limit — the existing `test/cli/upgrade-test.sh` passes those through.

**Keep Masterminds/semver/v3** (currently indirect) as a direct dependency for `Release.Version`. It's pure-Go, tiny, actively maintained, and preserves *identical* comparison semantics (including the leading-zero leniency the `vYYYY.MM.DD` tags rely on and the `String()` normalization the current "is available" line already prints). ## Atomic-replace design (per OS)

Reimplement `update.Apply`'s proven sequence in `apply.go`, into the **same directory** as the target (rename can't cross filesystems, and same-dir siblings guarantee that):

1. Stat the target to capture its current mode (default `0o755`).
2. Write `&lt;dir&gt;/.&lt;name&gt;.new` (`O_CREATE|O_WRONLY|O_TRUNC`, captured mode), copy bytes, **`Close()` before renaming** (Windows won't rename an open file).
3. `os.Remove(&lt;dir&gt;/.&lt;name&gt;.old)` (stale cleanup; required on Windows where rename fails if dest exists).
4. `os.Rename(target, .old)` — **works on Windows even for the running exe** (Windows permits renaming a running image; it only forbids deleting/overwriting it). This is the key cross-platform property.
5. `os.Rename(.new, target)`. On failure, roll back `os.Rename(.old, target)`; if rollback also fails, return a distinguishable error advising manual recovery.
6. `os.Remove(.old)`; if that fails (Windows running-exe lock), `hideFile(.old)` — `SetFileAttributesW(FILE_ATTRIBUTE_HIDDEN)` via `syscall.NewLazyDLL` on Windows, no-op elsewhere. This reproduces the "rename-and-hide" behavior the requirements call out, with **no `x/sys/windows` dependency** (matches go-update's own approach).

`ExecutablePath` = `os.Executable()` then `filepath.EvalSymlinks` on all platforms. Symlink resolution is **load-bearing**: `install.sh --bare-metal` symlinks `/usr/local/bin/orva → /opt/orva/bin/orva`, so `orva upgrade` must replace the real target, not the symlink. (`EvalSymlinks` is correct cross-platform in modern Go; I'm intentionally dropping go-selfupdate's Windows `GetFinalPathNameByHandle` path to keep one code path and avoid `x/sys` — a documented, minor behavioral simplification for exotic mapped-drive cases.)

Optional hardening worth noting: `assertWritable` currently probes the *file* for `O_WRONLY`, but atomic replace really needs the *directory* writable (it creates `.new`/`.old` there). I'd keep the file-probe for UX parity but add a directory-writability check behind the same sudo-hint — a strict improvement, not a regression.

## Honest trade-offs

**You now own cross-platform binary replacement forever.** That's the real cost, and it's concentrated in ~40 lines of `Apply` + `hideFile`. Mitigating factors specific to Orva: the algorithm is the long-battle-tested inconshreveable/go-update logic (I'm transcribing, not inventing); the risky surfaces — Windows running-exe rename+hide, symlink resolution for the bare-metal symlink, partial-write rollback — are all handled by that sequence; and Orva already runs OS-native upgrade E2E on all three platforms plus the Linux round-trip, so regressions surface in CI. Residual risks you inherit are inherent to *any* self-updater regardless of library: antivirus false-positives on live-exe rename, and a cross-device target (mitigated by same-dir siblings). Set against that: the alternative is shipping deprecated, unmaintained OpenPGP crypto in your server binary indefinitely with **no upstream fix path**, plus ~8 transitive dependencies (a full GitHub/GitLab/Gitea SDK stack) you don't use. For a self-hosted serverless platform, owning a small, auditable updater is the more defensible long-term posture than depending on an abandoned one. The one dependency I deliberately *keep* is Masterminds/semver/v3 — buying exact version-compare parity for a trivial, well-maintained, pure-Go cost.

Net: one import removed from `upgrade.go` clears the vuln in both binaries; the code Orva takes on is small, mostly already written, fully testable, and CGO-free/pure-Go static as `cli/CLAUDE.md` requires.
