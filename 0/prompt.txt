## Build seccomp profile = `default` + network + 17

**Proven by one-at-a-time removal against real installs:**
- `symlink` — npm: `npm error code EPERM` (writes `node_modules/.bin` links)
- `listxattr`, `utimensat` — pip: `ERROR: Exception:` (CPython `shutil.copystat` → `os.listxattr` / `os.utime`; it tolerates ENOTSUP/ENODATA/EINVAL/EACCES but **not** EPERM)
- `fsync` — pip: `Could not install packages due to an OSError: [Errno 1] Operation not permitted`

**Architecture parity** (aarch64 glibc routes the observed operation through these; the base set has no aarch64-valid `rename` path at all, and the traced install renamed 617×): `symlinkat`, `linkat`, `renameat`.

**Observed in trace, not strictly required on amd64:** `pwritev` (529 calls; libuv falls back on EPERM), `link` (1 call), `vfork` (esbuild's postinstall shell) + `fork`; plus symmetric `preadv`, `fdatasync`. `fork`/`vfork` are strictly weaker than the already-permitted `clone`.

**Contained process control:** `kill`, `tgkill` — not exercised by the validated workloads; included because a postinstall that cannot signal its own children (or `abort()`) hangs, and both are confined to the jail's PID namespace.

**Log hygiene, proven:** `sched_getparam`, `sched_getscheduler` — nsjail's NSTUN threads call `pthread_getschedparam`; denying it sprayed `[mutex.cc:955] RAW: pthread_getschedparam failed: 1` into build output. Allowing them removed it.

Not needed: `chown`/`fchown*` — a root-run install (the Docker case) traced identically, no chown. `capget`, `io_uring_*`, `clone3` stay denied; both runtimes handle it. Enumeration was `strace -ff` of real jailed `npm install` (lodash+axios+typescript+esbuild-with-postinstall) and `pip install` (requests+pydantic), as both uid 1000 and root.

## Risks / not done

1. **arm64 never executed** — no hardware here. Mitigated by `TestBuildProfileCompilesOnArm64` and by only naming syscalls present in the asm-generic table; a wrong name is a Kafel compile error that would take *every* arm64 build down. Worth one arm64 CI run before release.
2. **Per-deploy package cache is gone.** HOME is a throwaway dir per step, so npm/pip no longer reuse a cache across deploys (Docker root previously had `/root/.npm`; bare metal's `--no-create-home` orva user likely never did). Repeat deploys re-download. Fix would be binding a persistent `&lt;dataDir&gt;/build-cache` and setting `npm_config_cache`/`PIP_CACHE_DIR` — deliberately **not** done: it is a shared mutable directory across mutually-distrusting builds and I could not validate that trade-off in scope.
3. **`~/.npmrc` / `pip.conf` no longer apply** (fresh HOME). Mitigated by forwarding `NPM_CONFIG_*`, `npm_config_*`, `PIP_*` and the proxy vars from orvad's environment; daemon secrets are not forwarded (tested).
4. **Install timeouts unchanged** — I deliberately did not impose `build_timeout_seconds` on installs (that would newly fail slow large installs); `--time_limit 0` keeps nsjail's own 600 s default from introducing a cutoff that did not exist before. tsc keeps its existing timeout, now via `sandbox.ErrBuildTimedOut`.
5. Build memory/pids are constants (2048 MB / 256), enforced only where cgroup v2 is delegated — same caveat the worker path already has.
6. I did **not** run the authoritative suites (`test/e2e/run.py`, `test/run-all.sh`) — verification here is `make lint`/`make test` plus the live-instance evidence above.
